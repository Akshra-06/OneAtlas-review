# Master UI Generation Guidelines

> **Core Design Intelligence Layer for OneAtlas AI Generation System**

This document defines the design philosophy, rules, and systems that control how AI generates product-quality applications. It is NOT a generic UI guideline document—it is the instruction brain for the entire OneAtlas generation system.

**Goal:** Generated apps should feel more polished, modern, contextual, and product-native than Lovable/Base44-style outputs.

---

## 1. Product Design Philosophy

### AI-Native UX Principles

**Principle 1: Intelligence-First Design**
- UI should reflect that it was generated by an intelligent system, not a template engine
- Every element should have a reason for its existence based on domain, workflow, or user intent
- Avoid "because it's there" design decisions

**Principle 2: Workflow-Native Interaction**
- UI should flow around user tasks, not data structures
- Primary actions should surface based on workflow frequency and importance
- Secondary actions should be contextually available, not always visible

**Principle 3: Adaptive Density**
- Information density should match domain expectations
- Healthcare = comfortable, breathing room
- Analytics = high density, data-rich
- CRM = pipeline-focused, action-dense
- Ecommerce = operational, fulfillment-oriented

**Principle 4: Contextual Hierarchy**
- Visual hierarchy should emerge from operational importance, not arbitrary sizing
- Section ordering should reflect workflow sequence, not alphabetical or random
- Emphasis should guide users to their next action, not decorate the page

### Modern SaaS Design Philosophy

**Product-First vs CRUD-First Generation**

**CRUD-First (Avoid):**
- Generic tables for every entity
- Create/Edit/Delete buttons as primary actions
- Flat dashboards with equal visual weight
- Repeated card grids
- No workflow context

**Product-First (Require):**
- Workflow-driven layouts
- Operational dashboards tailored to domain
- Contextual action areas
- Information hierarchy based on user goals
- Domain-specific widgets and interactions
- Adaptive composition based on archetype

**Enterprise vs Consumer UX Behavior**

**Enterprise UX:**
- Higher information density
- More controls visible
- Keyboard navigation priority
- Data-rich tables
- Multi-step workflows
- Role-based access patterns
- Audit trails visible

**Consumer UX:**
- Lower information density
- Progressive disclosure
- Touch-friendly interactions
- Visual-first presentation
- Single-step flows
- Simplified controls
- Feedback-heavy interactions

### Information Hierarchy Principles

**Principle 1: Operational Dominance**
- Most frequent actions get most visual prominence
- Critical workflow steps get primary placement
- Secondary information gets secondary placement
- Tertiary information gets contextual access

**Principle 2: Domain-Aware Prioritization**
- Healthcare: Patient status, appointments, alerts
- CRM: Pipeline movement, lead actions, follow-ups
- Analytics: Insights, trends, anomalies
- Ecommerce: Orders, inventory, fulfillment status

**Principle 3: Visual Rhythm**
- Establish clear visual patterns
- Use spacing to create breathing room
- Use typography to create hierarchy
- Use color to guide attention
- Use motion to indicate state

## 2. Visual Hierarchy System

### Section Importance Scoring

**Scoring System (0-10):**
- **10 (Critical):** Primary workflow actions, status indicators, alerts
- **8-9 (High):** Dashboard KPIs, primary navigation, main content areas
- **6-7 (Medium):** Secondary actions, supporting information, contextual panels
- **4-5 (Low):** Settings, help, documentation, tertiary navigation
- **0-3 (Minimal):** Footer, legal, version info

**Application Rules:**
- Critical sections get top placement and largest visual weight
- High sections get prominent placement and strong visual weight
- Medium sections get contextual placement and moderate weight
- Low sections get secondary placement and subtle weight
- Minimal sections get minimal placement and lightest weight

### Typography Scaling Rules

**Base Scale (16px):**
- **H1:** 32px (2.0x) - Page titles, main headings
- **H2:** 24px (1.5x) - Section headings
- **H3:** 20px (1.25x) - Subsection headings
- **H4:** 18px (1.125x) - Card titles
- **Body:** 16px (1.0x) - Body text
- **Small:** 14px (0.875x) - Labels, metadata
- **Tiny:** 12px (0.75x) - Captions, footnotes

**Archetype Adjustments:**
- **Healthcare:** 1.1x scale (softer, more readable)
- **Analytics:** 0.9x scale (more data fits)
- **CRM:** 1.0x scale (balanced)
- **Ecommerce:** 1.0x scale (balanced)

**Line Height Rules:**
- Headings: 1.2-1.3 (tighter)
- Body: 1.5-1.6 (readable)
- Small: 1.4-1.5 (compact but readable)

**Font Weight Hierarchy:**
- **Bold (700):** Critical actions, alerts, primary navigation
- **Semi-bold (600):** Section headings, important labels
- **Medium (500):** Card titles, emphasis text
- **Regular (400):** Body text
- **Light (300):** Metadata, captions

### Spacing System

**Base Unit: 4px**

**Scale:**
- **2xs:** 4px (tight spacing)
- **xs:** 8px (compact spacing)
- **sm:** 12px (comfortable spacing)
- **md:** 16px (standard spacing)
- **lg:** 24px (generous spacing)
- **xl:** 32px (section spacing)
- **2xl:** 48px (major section spacing)
- **3xl:** 64px (page spacing)

**Archetype Adjustments:**
- **Healthcare:** 1.2x scale (more breathing room)
- **Analytics:** 0.8x scale (denser)
- **CRM:** 1.0x scale (balanced)
- **Ecommerce:** 1.0x scale (balanced)

**Application Rules:**
- Use consistent spacing within sections
- Use larger spacing between sections
- Use spacing to create visual groups
- Use spacing to indicate hierarchy

### Visual Rhythm

**Principle 1: Consistent Patterns**
- Establish a rhythm for section spacing
- Use consistent padding within cards
- Use consistent margins between elements
- Use consistent gap sizes in grids

**Principle 2: Breathing Room**
- Don't crowd content
- Use whitespace to separate concerns
- Use whitespace to guide the eye
- Use whitespace to reduce cognitive load

**Principle 3: Visual Flow**
- Guide the eye from most important to least important
- Use spacing to create visual paths
- Use alignment to create visual connections
- Use grouping to create visual relationships

### Adaptive Density

**Density Levels:**
- **Dense:** High information density, minimal spacing (analytics, finance)
- **Compact:** Medium information density, moderate spacing (CRM, ecommerce)
- **Comfortable:** Low information density, generous spacing (healthcare, education)
- **Spacious:** Very low information density, very generous spacing (consumer apps)

**Adaptation Rules:**
- Match density to domain expectations
- Match density to user expertise
- Match density to screen size
- Match density to workflow complexity

### Dominant/Secondary UI Areas

**Dominant Areas:**
- Primary workflow actions
- Critical status indicators
- Main content areas
- Primary navigation

**Secondary Areas:**
- Secondary actions
- Supporting information
- Contextual panels
- Secondary navigation

**Tertiary Areas:**
- Settings
- Help
- Documentation
- Tertiary navigation

**Application Rules:**
- Dominant areas get 60-70% of visual weight
- Secondary areas get 20-30% of visual weight
- Tertiary areas get 10-20% of visual weight
- Use size, color, and placement to indicate hierarchy

### Attention Mapping

**Attention Zones:**
- **Zone 1 (Primary):** Top-left, center-top (most attention)
- **Zone 2 (Secondary):** Center, right-top (moderate attention)
- **Zone 3 (Tertiary):** Bottom-left, bottom-right (least attention)

**Mapping Rules:**
- Place critical elements in Zone 1
- Place important elements in Zone 2
- Place supporting elements in Zone 3
- Use visual weight to reinforce attention zones

**Sidebar Types:**
- **Fixed:** Always visible (desktop)
- **Collapsible:** Can be collapsed/expanded

**Hierarchy Levels:**
- **Level 1:** Primary navigation (main sections)
- **Level 2:** Secondary navigation (subsections)
- **Level 3:** Tertiary navigation (items within subsections)
- **Level 4:** Quaternary navigation (rare, specific items)

**Display Rules:**
- Level 1: Always visible (sidebar or topbar)
- Level 2: Visible in sidebar or dropdown
- Level 3: Visible in sidebar or sub-menu
- Level 4: Visible in sub-menu or context menu

**Archetype Adjustments:**
- **Healthcare:** 3 levels (patient-centric hierarchy)
- **Analytics:** 2 levels (flat, data-focused)
- **CRM:** 3 levels (pipeline hierarchy)
- **Ecommerce:** 2 levels (operational focus)

### Responsive Composition

**Breakpoints:**
- **Mobile:** < 640px

- **Large Desktop:** > 1440px

**Composition Rules:**

- Large Desktop: Multi-column, expanded grid

**Content Rules:**
